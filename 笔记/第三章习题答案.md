## 习题 1

### 题目

给定迷你语料库：

```text
datawhale agent learns
datawhale agent works
```

1. 计算句子 `agent works` 在 Bigram 模型下的概率。  
2. 解释 N-gram 的马尔可夫假设，并说明它的主要局限。  
3. 说明 RNN / LSTM 和 Transformer 分别如何改进 N-gram。

---

### 解答

#### 1. Bigram 概率计算

语料库总词数为 6，`agent` 出现 2 次，因此：

`P(agent) = 2 / 6 = 1 / 3`

词对 `agent works` 出现 1 次，而 `agent` 共出现 2 次，因此：

`P(works | agent) = 1 / 2`

所以：

`P(agent works) = P(agent) × P(works | agent) = (1 / 3) × (1 / 2) = 1 / 6 ≈ 0.167`

**答案：** `P(agent works) = 1 / 6 ≈ 0.167`

---

#### 2. 马尔可夫假设与 N-gram 局限

**马尔可夫假设：**  
当前词的概率只依赖前面有限个词，而不是依赖全部历史信息。

例如：

- Bigram：只看前 1 个词
- Trigram：只看前 2 个词

**N-gram 的主要局限：**

1. **数据稀疏**：没见过的词组概率可能直接为 0。  
2. **泛化能力差**：不能理解语义相近的词。  
3. **上下文固定**：只能看固定长度的前文，难以处理长距离依赖。  

---

#### 3. RNN / LSTM 和 Transformer 的改进

**RNN：**  
引入 Hidden State（隐藏状态），可以不断传递历史信息，不再局限于固定窗口。

**LSTM：**  
在 RNN 基础上加入门控机制（遗忘门、输入门、输出门），更适合保留长期信息，缓解长期依赖问题。

**Transformer：**  
使用 Self-Attention（自注意力机制），可以直接建模任意两个 Token 之间的关系，并支持并行计算。

**对比总结：**

- **N-gram**：统计方法，简单，但上下文短、泛化差  
- **RNN / LSTM**：能利用更长历史信息，但计算是串行的  
- **Transformer**：能处理长距离依赖，且训练效率更高  

---

#### 总结

```text
N-gram
↓
固定窗口，数据稀疏，泛化差

RNN / LSTM
↓
能记住更长历史信息

Transformer
↓
Attention 建模全局关系，并行计算能力更强
```

## 习题 2：Transformer 架构

### 题目

1. Self-Attention（自注意力机制）的核心思想是什么？
2. 为什么 Transformer 可以并行处理序列，而 RNN 必须串行处理？Positional Encoding（位置编码）起什么作用？
3. Decoder-Only 与完整的 Encoder-Decoder 架构有什么区别？为什么现代主流大语言模型普遍采用 Decoder-Only？

---

### 解答

#### 1. Self-Attention 的核心思想

Self-Attention 让每个 Token 根据当前上下文判断其他 Token 对自己的重要程度，并融合相关信息形成新的上下文表示。

```text
当前 Token 的 Q
↓
与所有 Token 的 K 计算相关性
↓
Scaling + Softmax
↓
得到 Attention Weight
↓
对所有 V 加权求和
↓
得到融合上下文后的新表示
```

其中：

- Q（Query）：当前需要寻找什么信息
- K（Key）：各 Token 提供什么信息
- V（Value）：真正被提取和融合的内容

---

#### 2. 并行计算与位置编码

RNN 需要按顺序处理：

```text
Token 1
↓
Token 2
↓
Token 3
```

后一个 Token 依赖前一个 Hidden State，因此难以并行。

Transformer 不依赖循环结构，可以对整段序列同时计算 Attention：

```text
完整序列
↓
并行计算 Token 之间的关系
```

因此训练效率更高。

但 Self-Attention 本身不知道 Token 的先后顺序，所以需要 Positional Encoding（位置编码）：

```text
Token Embedding
+
Positional Encoding
↓
同时包含语义信息和位置信息
```

---

#### 3. Decoder-Only vs Encoder-Decoder

### Encoder-Decoder

```text
Source
↓
Encoder
双向理解完整输入
↓
Source Representation
↓
Decoder
Masked Self-Attention
+
Cross-Attention
↓
生成 Target
```

Decoder 会同时参考：

- 已生成的 Target 前文
- Encoder 对完整 Source 的理解

### Decoder-Only

```text
Prompt + 已生成内容
↓
Causal Self-Attention
↓
FFN
↓
预测下一个 Token
↓
加入 Context
↓
继续生成
```

Decoder-Only 没有独立 Encoder，也不需要 Cross-Attention，而是把输入和输出统一放在同一条 Context 中。

现代 LLM 普遍采用 Decoder-Only，主要因为：

1. 架构更简单，训练目标统一为“预测下一个 Token”
2. 天然适合自回归文本生成
3. 能方便地把各种任务统一成 Prompt → Completion 的形式
4. 容易扩展到大规模预训练

---

### 总结

```text
Self-Attention
→ Token 之间直接交换信息

RNN
→ 串行计算

Transformer
→ Attention 支持并行计算
→ Position Encoding 补充顺序信息

Encoder-Decoder
→ 输入理解与输出生成分开

Decoder-Only
→ 所有已有内容统一放入 Context
→ 自回归预测下一个 Token
```

## 习题 3：文本分词与 BPE

### 题目

文本子词分词算法会将文本转换为模型可处理的 Token 序列。请回答：

1. 为什么不能直接使用“字符”或“单词”作为模型的输入单元？
2. BPE（Byte Pair Encoding，字节对编码）解决了什么问题？

---

### 解答

#### 1. 为什么不能直接按字符或单词分词

**按单词分词（Word-based）的问题：**

- 词表会非常大，管理和训练成本高
- 容易出现未登录词（Out-Of-Vocabulary, OOV）
- 相近词形之间难以共享信息，例如 `look`、`looks`、`looking`

**按字符分词（Character-based）的问题：**

- 单个字符通常语义较弱
- 文本会被切得很长，Token 数增多
- 模型需要额外学习字符如何组合成有意义的词，效率较低

因此现代模型通常采用 Subword Tokenization（子词分词），在词表大小和语义表达能力之间取得平衡。

---

#### 2. BPE 解决了什么问题

BPE（Byte Pair Encoding）通过不断合并语料库中最高频的相邻 Token Pair，逐步构建子词词表。

```text
基本字符
↓
统计相邻 Token Pair
↓
合并最高频 Pair
↓
加入 Vocabulary
↓
重复
```

它的主要作用是：

- 控制 Vocabulary（词表）大小
- 减少 OOV 问题
- 常见词可以保留为完整 Token
- 低频或新词可以拆成多个 Subword Token 组合表示

因此，BPE 在“按字符分词”和“按单词分词”之间取得了较好的平衡。
